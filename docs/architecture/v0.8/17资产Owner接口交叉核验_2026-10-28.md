## Owner Port 最小事务契约（F1-01 / W2-04）

输入读取：GUI、CLI与Agent一律委托同一领域`XX.Port.readExact`，C0只持有`domain/kind/id/revision/contentHash/schemaVersion/scope`及适用时`frameRef`；C1由Owner持有业务DTO，不引入巨型公用对象。几何Frame必须具名右手坐标、明确from/to与单位；显示用Babylon矩阵只用于渲染，不写回业务状态。字节型CAD/STEP/CL/NC摘要按原始字节Hash；JSON若采用RFC8785标准化Hash，必须显式标记规范化配置与算法版本，不能混作原始字节相等。

写入过程：`propose → previewLease → validate → humanApproval(where required) → OwnerPort.commitWithCAS → immutableReceipt → invalidateConsumers`。Owner事务提交瞬间重验ACL、ScopeEpoch、expectedRevision/Hash/Frame、CAS、cancelGeneration与原目标；过期基线/撤权/取消/消费者NACK须拒绝或暂缓，不得以GUI成功动画替代回执。取消前若真实已提交，保存不可变receipt并对账；取消后的迟到ACK不得恢复新写入资格。只在成功后将新Revision加入来源图，禁止覆写冻结D08/历史D16。

## 关键跨域切片与反例

- **D03→D04与D10**：D03是可用资源目录；D04是名义Setup及毛坯Frame；D10是特定机床、载体、工件偏置和刀具总成真实安装绑定。D04调整不等于D10自动改写。反例：把D03默认刀柄Mesh直接当D10实测Gauge，拒绝。
- **D05↔D06→D08**：06域可在无D05人工计划下自主求解并返回候选；只有05域采纳/冻结，A/B共享同一工程事实但不得修改已冻结Revision。反例：求解Run返回成功即覆盖D08，拒绝。
- **D09→D12→D13→D14→D15→D16**：07域中立CL；08域后处理最终NC并解释控制器模态/偏置/刀补/宏循环；09域展开真实轴时序及独立NC工程验证；10域批准签发。D11可做CL_ONLY提示但不能授D15能力。任何D13未建模语义应为UNKNOWN并阻D16，绝不暗做材料扫掠仿真。反例：由CL画面直接签发，拒绝。
- **D16→D17→D05/D06**：现场记录/报警/质检是只追加观测，不自动等于控制器执行完成、检测合格或复机批准。反例：OPC顶层ServiceResult Good但单节点Bad仍判D17完全成功，拒绝；应检查每项StatusCode。

## 独立消费者准入与迁移

每个Dxx均应由**非生产域**至少一名消费者Owner提供真实读样例：exact revision/hash/frame/units/ACL、Schema兼容或显式UNKNOWN、负例撤权与取消重放、旧数据只读隔离及rollbackRef。读取当前`latest`不可替代exact version。退出标准：17份`Owner签署(签署人/职责/时间/decision/风险接受)`与17份`独立消费者回执(测试代码/运行环境/真实结果/回退)`；目前均为**PENDING_HUMAN / NOT_RUN**，严禁伪填。

GUI在单Babylon Engine/Scene/Canvas上展示多个逻辑世界横向切换，活动时只渲染一个；左侧UnifiedTaskPanel为唯一任务容器，浅/深主题，字体≤12px。显示通过和3D预览不具有任何写入或上机资格。
