# B18｜Git对象模式对Markdown本地链接资格的补证

**2026-10-29；NEWLY_AUTHORED；规划研究增量，不代表真实全仓GFM AST或产品验收。**

## 实质发现

B16工具按Git Tree路径存在与Markdown Token/锚点推导候选PASS，但固定Git对象还存在关键类型差异：普通文件`100644/100755`、符号链接`120000`以及gitlink `160000`。GitHub官方Git Trees文档明确这些mode/type定义；将`120000`的Blob或`160000`的Commit当成普通文档路径，可导致错误的PASS或错误的缺失REJECT。B18不改历史B16源码及合成记录，新增只读mode-aware封装，在真实Git对象树中对特殊模式本体与路径前缀统一输出`UNKNOWN_GIT_SYMLINK`/`UNKNOWN_GITLINK`，不推断跨仓内容，也不自动解引用。

固定原规划分支commit `ac9799610643801430d1bbb6dfec2613a931e72b` → Git Tree `aa3d4e8d793f93f6abafa493ce71c44138c5769e`：通过GitHub连接器完整读取1639条Tree项（truncated=false），其中1493普通Blob、146 Tree、**0符号链接及0 gitlink**，545份Markdown。本轮是对**未来特殊模式**的预防性修正，而非宣称在当前仓真实发现Git链接问题；下一HEAD必须重新计数。
