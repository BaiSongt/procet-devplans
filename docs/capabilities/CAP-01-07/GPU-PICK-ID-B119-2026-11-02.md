## 1. 新证据与适用边界

- Babylon官方Mesh Picking说明，v8.0起提供`GPUPicker.pickAsync`，GPU结果返回`thinInstanceIndex`；改变thin instance buffer或实例列表需要重新`setPickingList`，禁用Mesh须先从list移走再禁用；GPU路径中`visibility=0`与`isVisible=false`行为不同。**原始数字Index是渲染缓存槽位，不是D01/D03业务身份。**
- Babylon Scene.pick默认可检查Mesh的enabled/visible/isPickable；GPUPicker的PickList出于性能不会执行相同的禁用检查。CPU/GPU拾取不可假定过滤语义等价，且不能靠`mesh.name`或`thinInstanceIndex`作为持久化CAD occurrence。
- W3C Pointer Events Level 3 2026-06-30正式Recommendation的§4.2.7/4.2.11规定`pointercancel`与`lostpointercapture`，其Click事件仍可能依据此前捕获目标派发；故`pointerup`/Click不是领域提交命令的充分条件。W3C于2026-10-08另有Level 4 Working Draft，未据草案宣称新强制条款。
- WCAG 2.2 Recommendation 2024-12-12 的2.5.7要求可用非拖拽单指针替代（存在规定的例外），2.5.8为至少24×24 CSS像素或合格例外；**12px最大字体约束不构成缩小点击热区的理由**，但不直接认定Electron现有界面已符合WCAG。
- 来源中Babylon官网为持续更新页；未取得产品锁定npm精确版本，必要的产品版本差异和Pick行为只能在产品测试阶段实测；本规范禁止把API文档当成实际安全认证。W3C原文仅指定章节实读，不声称其定义Procet领域CAS。

## 2. 新发现：同一Index可对应不同业务实例

假设时刻t0，渲染批量ThinInstance中`index=2`指向CAD实例A（D01 hash=hA、sceneEpoch=14、instanceMapRevision=7）。一次异步`pickAsync`发起后，切换制造资源空间，GPU映射更新为Revision8，`index=2`被复用给资源B。旧Promise在t1完成，仍返回数字2；如果UI仅用当前索引表解释，就会错误选中B。

**防线不是简单关闭旧Panel：**调用时冻结 `{spatialSessionId,sceneEpoch,activeRootId,pickListRevision,instanceMapRevision,scopeEpoch,documentInstanceId,pointerGestureId}`，回调时比较全部epoch，并按发起瞬间保存的 `renderSlot→{businessAssetId,exactRevision,contentHash,occurrencePath,sourceFrame,renderFrame}` 解析。任意身份映射已经变化则`STALE`，只有Index没有ExactRef则`UNKNOWN`，不进行隐式重拾取并冒充同一次选择。

特别注意：GPU picking可命中`visibility=0`的对象；关闭Root时必须先更新PickList并让旧异步结果失效，再更新可见渲染状态。拾取命中只是`SelectionIntent`，不属于已认证拓扑、已采纳Setup或材料去除证明。

## 3. UI与业务Owner接口

- Shell仅一个Babylon Engine/Scene/Canvas；主工程/制造资源作为**同一Scene中互斥活动Root**横向切换，使用RendererPort注册同一`SpatialSelectionPort`。左侧唯一UnifiedTaskPanel展现候选、来源、变更与错误，不允许右Drawer与第二主3D。
- `beginPick(intent)`→`issueRendererPick(context)`→`resolvePickReceipt(receipt,issuedSnapshot)`→`inspectSelectionExactRef`→`presentSelectionCandidate`。`commitSelectionDerivedEdit`必须委托D01/D03/D04/D05领域Owner端口，并在实际写入点重新核对Actor ACL代际、exact revision/hash/frame、scopeEpoch与审批、CAS；相同GUI/CLI/Agent必须使用同一领域命令路径。只读拾取不触发持久化写入。
- 输出候选契约：`PickIntent {requestId,gestureId,sceneEpoch,pickListRevision,instanceMapRevision,scopeEpoch,activeRootId,renderSlot}`；`PickCandidate {renderRef,semanticExactRef?,sourceFrame?,renderFrame?,confidence:visual_only, status:CANDIDATE|UNKNOWN|STALE|REJECT|CANCELLED}`；以上只是设计候选Schema，原宿主API和Owner未签署。
- 事件`pointercancel/lostpointercapture/ESC`封闭当前gesture，不得让随后Click或Promise继续升格Commit。全程没有自动为3D预览注入工序批准，也不能让A/B共事实中的B模式覆盖冻结D08。
- 鼠标/触控拖拽选择须提供等价单击选择+列表定位或键盘可达入口；保持12px字体上限与适当的热区分离，针对1366×768/125%缩放进行实际可访问性测试；WCAG具体例外由审查人员记录，不预判全部3D CAD精细目标均适用24px阈值。

## 5. 失效、迁移、回退与跨域独立验收

- 改根、切项目/Setup、修改PickList、改变薄实例buffer或移除Mesh时，旧请求因epoch改变失效，不允许静默映射当前槽位；保存后D04/D05/D09按**精确依赖**失效，D08及D16冻结保留历史。取消后晚回执记`LATE_PICK_DISCARDED`，而不是写入。
- 旧数据若仅有`meshId/index`而缺少instanceMapRevision、CAD exactHash/occurrencePath和Frame，保留原始记录为`LEGACY_RENDER_ID_UNKNOWN`只读隔离，要求重新定位且人工确认；不可批量猜测或反向改写库存模型。迁移回退只切Reader/渲染路由，不删持久化Owner记录。
- D01/D03语义Owner独立验收实例选择，D04 Setup消费者验原Frame和CAS，D05/D08验冻结不覆盖；D13/D14/D15从最终NC和D10重新取证，D16发布与D17收件不能由CL/GPU播放升格。测试需记录产品exact HEAD、Babylon npm版本、Actor/ACL代际、Frame、场景代际与fixture输入，分别执行GPU与CPU拾取、薄实例重排、根切换、撤权、ESC、触控和低端GPU回退路径。不可替代实机运动或材料扫掠仿真。
- 未签署Owner0/17、实际独立消费者0/17、L3待人工审；真实Babylon/Electron/产品Node/OCCT/OEM/17消费者均`NOT_RUN`。规划PASS≠产品PASS。
