# CAP-08-08 独立消费者、离线验收与回退

## 交付端口与职责

- 08域D12 Owner：输入为D08/D09精确ref、D03/D04/D10分离的领域读引用、后处理插件/模板/属性/Profile/Runtime全闭包；输出候选D12最终NC原字节、生成活动、byteSpan映射、静态诊断及manifest。**先提案后CAS提交**。
- 08域D13独立解释器：必须通过`readExact(D12revision,bytesHash)`重新读取实际NC和子程序闭包，独立解析模态及控制器Profile；不把D12后处理产出的静态诊断当语义执行结果。
- 09域D14：持D10机床执行绑定展开轴运动时序；D04 Setup只提供工艺参考系，不能直接转成真实机器运动。
- 09域D15：独立消费者据D13+D14完成工程验证并记录证据、阈值来源及UNKNOWN；D16发布须另行审查批准，不得借D11 CL动画替代。

## 独立正反验收（**待执行**）

1. D12正常：同一输入/插件/属性/Runtime闭包形成稳定byte digest和关联修订，复验得到相同或记录非确定性字段；负例为仅改插件字节而不改展示版本，必须失效。
2. D13正常：从真实最终NC字节再次解析，并保存解释Profile/子程序闭包/调用栈；负例为D12静态PASS但NC含未知宏，必须UNKNOWN并阻D16。
3. D14/15正常：使用真实D10绑定、固件选件可核的配置，计算轴运动和独立报告；负例为D04变换当成D10绑定，必须拒绝。
4. GUI/CLI/Agent：三入口传相同command和scope，Owner提交结果一致；负例为权限撤销、CAS冲突、取消晚回执、Frame更新，均不能提交。
5. 历史回退：从新Profile回到旧成套D09+D12+D13+D14+D15证据和旧Reader；负例为只回退插件而保留新验证票据，必须STALE。历史D08冻结及旧D16发布记录不可删除。
