# CAP-01-01｜项目与工程空间

**规格版本：0.9.1-review｜第01批｜状态：评审稿，非实现或生产验收报告。**

原88项能力名称与编号保持；本文件的L4、逻辑命令名、字段和UI状态是新增细化建议。通过ADR与生产者/消费者评审后才能升级正式契约。

## 1. 用户目标与责任

让工艺工程师在一个受控工程中组织模型、多个 Setup、求解结果和发布记录；能够关闭、换机、离线重开并恢复现场。工程是领域成果的可见引用集合，不是将九仓数据库合并，也不是一个文件路径。

**参与者：** 工艺工程师、工程负责人；平台服务负责持久化与恢复。

**唯一写入责任：** Project Runtime 负责工程身份、引用提交与容器；各领域仍负责自己的权威内容。

**入口：** ActivityRail 顶部“工作区与文档”→工程；Ribbon“工程”→新建/打开/保存。无工程时仍可独立进入资源目录。

**关联数据：** EngineeringSnapshot、WorkContext、D01、D03、D04、D05、D08

**本批细化工作包：** B0-01、B0-04、F1-06、W2-04、U4-01

## 2. L4业务子能力

| 编号 | 子能力 | 具体规则 | 输入/意图 | 输出 |
|---|---|---|---|---|
| CAP-01-01-L4-01 | 创建与标识 | 新建只创建 ProjectId 与初始修订；工程名可重名，名称与路径都不是主键。不导入即计算毛坯。 | `Project.create` | `EngineeringSnapshot` |
| CAP-01-01-L4-02 | 打开与预检 | 先检验容器、Schema、必需模块和引用闭包，再挂载候选现场；失败保留原现场。 | `Project.openPreview` | `OpenReport` |
| CAP-01-01-L4-03 | 多文档与多Setup寻址 | 以 project/document/setup/plan 的稳定标识查询；列表打开顺序不改变模型或工艺归属。 | `Project.queryObjects` | `ObjectList` |
| CAP-01-01-L4-04 | 保存与另存 | 保存推进检查点；另存副本默认产生新工程身份并保留来源，迁移原文件只是变更存储位置。 | `Project.save / Project.fork` | `CommitReceipt` |
| CAP-01-01-L4-05 | 关闭与任务收束 | 关闭前列出未保存草稿与运行任务；暂存、保存、放弃分别操作，不把关面板当取消任务。 | `Project.closePreview` | `CloseDecision` |
| CAP-01-01-L4-06 | 恢复与诊断 | 区分工程资产、未采纳成果和会话偏好；缺少必需资产拒绝正常挂载，可显式进入诊断只读。 | `Project.recover` | `RecoveryReport` |

## 3. 端到端主流程

1. 用户选新建，输入名称与受控保存目标；模板可空。Host 验证可写权限后返回 ProjectId 与 generation。

2. 打开模型作为独立业务操作；工程列表先显示“导入中”，成功回执后才出现有效模型引用。

3. 用户切换多个 Setup；WorkContext 仅切换寻址和现场，不复制或重算已有特征。

4. 保存时领域准备冻结结果，Project 以 expectedGeneration 校验引用闭包后提交可见头，再执行已有 .pct 保存路径。

5. 某个域提交完成但工程提交冲突，保留域成果为未采纳，不覆盖别人新提交的工程。

6. 重开时在临时恢复区准备全部必需域，通过后一次切换可见工程；相机和布局最后恢复且不改变制造修订。

## 4. 页面、控件与3D行为

主页面标识：`UI-01-01`。每个页面状态挂载在同一TaskHost，不意味着新增独立窗口。

| 页面/状态 | 内容 | 可执行操作 | 空间/宿主约束 |
|---|---|---|---|
| 工程入口 | 最近工程与新建/打开，失败项显示路径缺失或权限原因 | 选中只预览概要；打开是明确命令 | 单容器，背景继续显示当前工程 |
| 工程概要 | 名称、检查点、对象统计、必需模块、未保存草稿 | 进入对象/版本/任务均保留ProjectId | 背景为活动项目场景 |
| 打开预检 | 模块、资产、Schema逐项结果及定位按钮 | 正常打开/诊断只读/取消，不伪造成功 | 原工程保持可见直到提交 |
| 关闭确认 | 按对象列出dirty与在途任务，给出具体处理 | 保存并关闭/暂存现场/放弃指定草稿/取消 | 不连带停止其他工程任务 |

### 4.1 通用操作语义

选中仅更新SelectionIntent；预览仅更新PreviewLease；输入仅修改所属EditSession；保存/采纳/批准分别调用领域用例。长时作业复用Host，TaskHost不另建运行队列。

页内字段实时检查只为反馈；后端必须重做必要校验。失败定位到字段或对象并保留草稿；回执与scopeEpoch不匹配只记为旧范围结果，不污染新范围。

关闭容器默认隐藏并按策略保留未提交现场；关闭工程则列出dirty与在途任务分别处置。只读/模块不可用状态保留查看与解释入口，不伪装可写。

### 4.2 状态矩阵

| 状态 | 字段与动作 | 退出条件 |
|---|---|---|
| loading | 保留旧视图或骨架；禁止重复写入 | 当前scope读取完成 |
| empty | 展示当前任务真实下一步，不造默认资源/业务结果 | 必需对象建立 |
| ready | 只执行后端声明可用的命令 | 用户编辑/执行/换范围 |
| dirty | 显示未提交标识；支持预览与放弃 | 领域回执或明确放弃 |
| readOnly | 内容可读，写命令禁用并解释 | 获得权限/派生Draft/切兼容范围 |
| backendUnavailable | UI可展示诊断，写操作不可用 | Host真实能力恢复 |
| conflict | 保留本地草稿与远端基线，禁止默认覆盖 | 重新加载、重评估或保留未采纳 |
| failed | 显示代码、阶段、来源和可恢复动作 | 修正输入/安全重试/退出 |

## 5. 字段级规格

以下是目标业务语义键，不意味着现有Rust/TypeScript wire字段同名。正式映射须在Adapter表中记录来源与转换，禁止绕过旧契约直接改数据库。

| 用户可见字段 | 语义键 | 类型/单位 | 权威来源 | 编辑与校验规则 |
|---|---|---|---|---|
| 名称 | displayName | 文本，必填 | 工程元数据 | 创建/重命名可改；保留独立ProjectId |
| 工程标识 | projectId | 只读稳定ID | Project | 禁止以文件名替代 |
| 保存位置 | locationHandle | 文件选择授权句柄 | Host | 不把任意本机路径作为跨仓业务字段 |
| 当前检查点 | generation | 只读非负整数 | Project | 服务端提交后更新；前端不自增 |
| 来源工程 | forkOf | 可空ExactRef | Project | 新副本记录来源，不篡改祖先 |
| 所需模块 | requiredModules | 版本/能力列表 | 组合锁与工程manifest | 缺必需项阻断，缺可选项隔离只读 |
| 存储状态 | persistenceState | 未保存/已保存/冲突 | Project读模型 | 与领域批准和任务成功分开 |
| 工作现场 | activeContext | 文档/Setup/任务引用 | 会话服务 | 用户偏好，不计入制造内容hash |

## 6. 命令、查询、回执与事件

逻辑能力名用于设计追踪；已存在后端命令应复用或受控适配，不要求按本表重命名Tauri command。GUI、CLI、Agent不得绕开Host及领域校验。

| 逻辑命令/查询 | 必需输入 | 成功返回 | 拒绝/冲突路径 |
|---|---|---|---|
| project.create | 名称、目标句柄、可选模板ExactRef | ProjectRef+初始generation | 路径拒绝/模板不可用；失败不留可见半工程 |
| project.open | 容器句柄、openPolicy | OpenReport+挂载回执 | 必需模块/资产缺失；旧现场不变 |
| project.save | ProjectId、expectedGeneration | CommitReceipt+持久化检查点 | CAS冲突/磁盘不足；保留上次可用文件 |
| project.fork | 源ExactRef、新目标句柄 | 新ProjectId+来源引用 | 不复制外部审批资格，不重写旧hash |

建议事件：`project.head.committed`、`project.persistence.failed`、`project.workspace.closed`。

写入前核对作用域、预期修订、幂等键和领域要求。同步命令成功必须有真实回执；异步提交只返回JobRef并不算业务完成。安全身份由Host从会话获得，body里的Actor声明不授信。

## 7. 异常、边界与变更影响

保存未落盘时不得提示“已保存”；磁盘、解压、哈希和必需域错误分别呈现。恢复只读不自动升级历史 Schema。多库操作没有未经证明的全局 ACID 承诺。

工程类变更沿领域贡献的依赖用途传播；布局/相机不触发制造数据失效。跨数据库只通过受管staging与回执协调，不把多个本地库声称为同一个ACID事务。旧资产在已提交引用仍存续时不得被清理。
