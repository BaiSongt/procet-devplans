# CAP-01-06｜统一任务与事件中心

**规格版本：0.9.1-review｜第01批｜状态：评审稿，非实现或生产验收报告。**

原88项能力名称与编号保持；本文件的L4、逻辑命令名、字段和UI状态是新增细化建议。通过ADR与生产者/消费者评审后才能升级正式契约。

## 1. 用户目标与责任

提供统一且可追溯的长时任务、问题、日志和输出入口。任务“运行成功”不代表结果已提交到工程，更不代表已经验证或批准；关闭任务面板不应中断后台Worker。

**参与者：** 全部业务用户、Agent调用者、运维与本地验收者。

**唯一写入责任：** 现有Host Job/Dispatcher/Journal是运行事实唯一来源；MessageBus为界面投影，领域持有成果与验证事实。

**入口：** 底部消息中心标题与分组计数同一行；ActivityRail任务入口；业务命令启动后自动出现任务项而非强抢焦点。

**关联数据：** WorkContext、EngineeringSnapshot、D06、D07、D09、D12、D13、D14、D15

**本批细化工作包：** B0-01、F1-05、W2-04、U4-02、U4-04、T5-01

## 3. 端到端主流程

1. 业务命令通过Host校验输入、权限、预算及幂等后创建任务；返回HostJobId和观察流。

2. 底部消息中心显示“任务|问题|日志|输出”计数；单任务摘要包含能力、所属工程、输入修订和实际进度。

3. 用户可以继续编辑或换Setup；任务上下文固定，不随当前UI现场漂移。

4. 取消按钮先进入“正在取消”，禁止继续向相同任务提交新写入；已发生提交不能用取消标签掩盖。

5. 任务完成先记录成果，结果未采纳/采纳冲突/已采纳分别展示；生产验证与批准再单独显示。

6. 断线或软件重启后从Journal恢复，按持久化回执判断是否提交；不支持恢复的Worker明确终止并允许新尝试。

## 4. 页面、控件与3D行为

主页面标识：`UI-01-06`。每个页面状态挂载在同一TaskHost，不意味着新增独立窗口。

| 页面/状态 | 内容 | 可执行操作 | 空间/宿主约束 |
|---|---|---|---|
| 消息中心摘要 | 消息中心 | 任务:n | 问题:n | 日志:n | 输出:n | 计数过滤只改投影，不清除Journal | 底部折叠面板，状态汇入状态栏 |
| 任务详情 | 阶段、输入、Worker版本、取消性、预算、产物 | 取消/查看成果/定位对象/重试预检 | 详情在同一左侧任务容器 |
| 冲突成果 | 运行成功但工程头变化，成果保持未采纳 | 评估采纳或保留历史，不能一键强盖 | 状态用文字且可键盘定位 |
| 诊断列表 | 错误码、对象、字段、可恢复性 | 进入具体业务任务补齐条件 | 不抢走正在输入的焦点 |

### 4.1 通用操作语义

选中仅更新SelectionIntent；预览仅更新PreviewLease；输入仅修改所属EditSession；保存/采纳/批准分别调用领域用例。长时作业复用Host，TaskHost不另建运行队列。

页内字段实时检查只为反馈；后端必须重做必要校验。失败定位到字段或对象并保留草稿；回执与scopeEpoch不匹配只记为旧范围结果，不污染新范围。

关闭容器默认隐藏并按策略保留未提交现场；关闭工程则列出dirty与在途任务分别处置。只读/模块不可用状态保留查看与解释入口，不伪装可写。

### 4.2 状态矩阵

| 状态 | 字段与动作 | 退出条件 |
|---|---|---|
| loading | 保留旧视图或骨架；禁止重复写入 | 当前scope读取完成 |
| empty | 展示当前任务真实下一步，不造默认资源/业务结果 | 必需对象建立 |
| ready | 只执行后端声明可用的命令 | 用户编辑/执行/换范围 |
| dirty | 显示未提交标识；支持预览与放弃 | 领域回执或明确放弃 |
| readOnly | 内容可读，写命令禁用并解释 | 获得权限/派生Draft/切兼容范围 |
| backendUnavailable | UI可展示诊断，写操作不可用 | Host真实能力恢复 |
| conflict | 保留本地草稿与远端基线，禁止默认覆盖 | 重新加载、重评估或保留未采纳 |
| failed | 显示代码、阶段、来源和可恢复动作 | 修正输入/安全重试/退出 |

## 5. 字段级规格

以下是目标业务语义键，不意味着现有Rust/TypeScript wire字段同名。正式映射须在Adapter表中记录来源与转换，禁止绕过旧契约直接改数据库。

| 用户可见字段 | 语义键 | 类型/单位 | 权威来源 | 编辑与校验规则 |
|---|---|---|---|---|
| 任务名称 | displayName | 能力名+目标 | Host | 不只显示内部ID |
| 运行标识 | hostJobId | 稳定ID | Host | 与camJobId/viewTaskId分开 |
| 所属范围 | scope | 工程/资源目录判别联合 | Host | 没有工程的资源任务仍可运行 |
| 运行阶段 | runState | 离散运行态 | Host Journal | UI不模拟成功 |
| 进度 | progress | 完成量/总量或阶段文本 | Worker | 无总量不显示假百分比 |
| 成果状态 | adoptionState | 未产生/未采纳/已采纳/冲突 | 应用提交回执 | 与runState独立 |
| 诊断定位 | diagnosticLocator | 对象/字段/程序段 | 领域 | 点击按exact上下文打开 |
| 尝试来源 | retryOf | 可空HostJobId | Host | 新的尝试有新ID，幂等重取回执不新建任务 |

## 6. 命令、查询、回执与事件

逻辑能力名用于设计追踪；已存在后端命令应复用或受控适配，不要求按本表重命名Tauri command。GUI、CLI、Agent不得绕开Host及领域校验。

| 逻辑命令/查询 | 必需输入 | 成功返回 | 拒绝/冲突路径 |
|---|---|---|---|
| job.submit | capabilityId、scope、exact输入、预算、幂等键 | HostJobRef | 权限/必需输入/并发配额拒绝 |
| job.observe | HostJobId、afterSequence | 有序事件页+最新快照 | 事件间隙触发补齐，越权拒绝 |
| job.cancel | HostJobId、理由、取消代次 | 取消请求回执 | 不可取消阶段返回原因，不伪造cancelled |
| job.retry | 原任务ID、核对的输入、retryPlan | 新尝试或已有幂等回执 | 副作用未知先对账，不能盲重发 |

建议事件：`host.job.state.changed`、`host.job.artifact.ready`、`host.job.commit.conflicted`。

写入前核对作用域、预期修订、幂等键和领域要求。同步命令成功必须有真实回执；异步提交只返回JobRef并不算业务完成。安全身份由Host从会话获得，body里的Actor声明不授信。

## 7. 异常、边界与变更影响

Worker失联与任务失败分开；超时后存在未知提交状态时标reconciliationRequired并先查回执。日志与用户敏感路径脱敏。ARIA状态通知参考W3C，不让持续进度刷屏或抢焦点。[R01]

工程类变更沿领域贡献的依赖用途传播；布局/相机不触发制造数据失效。跨数据库只通过受管staging与回执协调，不把多个本地库声称为同一个ACID事务。旧资产在已提交引用仍存续时不得被清理。
