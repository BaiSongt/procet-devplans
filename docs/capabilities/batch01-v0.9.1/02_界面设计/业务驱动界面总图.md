# 业务驱动的桌面结构与首批10项任务设计

**本文件为目标交互规格，尺寸和性能指标属于建议验收基线，尚未通过Windows EXE实机验收。**

## 1. 先画用户旅程，再决定页面

### 旅程A：从空工程到可接管的探索结果

打开/新建工程（01-01）→导入与关联设计对象（01-02）→选择具体A探索目标及最低输入（01-05）→在统一任务中心观察运行（01-06）→保留候选来源与变化（01-03）→预览接管并进入B草稿（01-05）。审批和发布资格在适用节点独立执行（01-04），不是进入所有探索的先决条件。

### 旅程B：没有工程也能建立制造资源

进入资源空间（01-07）→建机床/刀具草稿（02-01/02-02）→结构和来源检查→授权发布（01-04）→供后续工艺Setup选用。机床/刀具目录的维护不是Setup中的一次性临时表单，也不能在这里填写工件任务专属偏置。

### 旅程C：从工序选择资源，再回到原现场

记录发起ScopeKey、目标Slot、expectedRevision、允许资源kind和返回TaskId→切换到同一Scene中的资源会话→选择并检查Released exact修订→后端确认与读回→核对发起Scope仍有效→返回原任务和相机。若原Setup已变化，拒绝旧写入并留下可重评估的选择；不能把资源写到此刻碰巧活动的另一个Setup。

### 旅程D：改参数后了解后果

在草稿修改→即时显示预览与字段提示→后端预检给出差异和失效集合→明确提交→生成新修订与审计→任务中心记录后续重算。界面必须把“保存资源”“采用建议到工序”“批准该修订”拆成不同动作。

## 2. Shell空间规则

保留唯一Babylon Engine/Scene/Canvas；主工程、资源世界横向切换，不并排。域模块只能提供RendererPort/Overlay数据，不自己new Engine。SpatialSession保存相机、选择与可见根；真值不从渲染矩阵反推。

固定ActivityRail顺序：顶部工作区与文档；其下是与当前制造任务对应的功能组；再下AI、文档、知识；底部专注3D与设置。不是把88个功能全部做成88个图标。十项本批功能通过工作区任务切换器、资源类别、上下文入口到达。Ribbon展示当前任务的高频动作和分组，不持有第二份业务导航真值。

左侧仅一个UnifiedTaskPanel/TaskHost，建议桌面默认宽380px。内部顶栏显示任务名、对象/修订、只读/草稿状态和关闭；主体分组滚动；底部固定主动作与次动作。工作区顶部不恢复中央文档Tabs；最近文档与对象选择放工作区入口。可选宽度调整应通过统一Preference token评审，禁止不同模块各自硬编码宽度。

底部状态栏统一承载单位、Frame、模型身份、选择数量、渲染状态和任务摘要；移除左右角散落状态。消息中心标题与分类计数同一行。OverlayInsets由同一安全区来源提供给HUD和相机适配，不能各自重复DOM测量。

主题只保留浅/深；液态玻璃为表面层样式，正文/输入对比优先。AI窗口使用同主题；流光只表达真实等待或Agent运行。减少动画模式关闭非必要过渡。GPU优先指渲染与大轨迹缓冲，不代表所有业务处理必须放GPU。

## 3. 交互状态与持久化分区

| 状态 | Owner | 是否制造修订 | 说明 |
|---|---|---|---|
| 工程及领域exact内容 | Project+各领域 | 是 | 保存可见引用及不可变内容 |
| A/B业务接管记录 | 应用编排+CAM | 是 | 记录继承来源、冻结与待补项 |
| 编辑草稿 | 领域EditSession | 仅明确提交后 | 不因面板关闭自动写生产数据 |
| HostJob运行与回执 | Host Journal | 独立运行事实 | 运行成功可能尚未采纳 |
| Workbench/AI-native | 用户偏好 | 否 | 展示模式 |
| 当前文档/Setup/任务 | WorkContext | 否 | 可寻址导航，不能充当业务前置条件 |
| 相机/选中/显示根 | SpatialSession | 否 | 真实模型未变时不影响制造hash |
| 审批有效性 | 领域+策略 | 版本化事实 | 历史批准决定与当前适用性分列 |

## 4. 页面通用组件与职责

`ObjectContextHeader`展示固定对象和修订；`RequirementList`展示缺失条件及精准导航；`RevisionBadge`打开来源/差异；`ParameterField`声明单位、权威来源、可编辑性和字段错误；`ResourcePicker`管理选择往返；`EvidenceSummary`展示已覆盖/未知；`TaskFooter`只执行域命令；`DiagnosticLink`定位对象或字段。

不把所有页面做成自动生成的JSON表单。身份、单位、枚举、列表可由字典驱动；运动轴树、装配关系、候选接管和几何选择是专用业务交互，仍由领域TaskContribution实现，但共享编辑与提交协议。

## 5. 关键按钮规则

“预览”不写工程；“保存草稿”提交草稿并返回修订；“采用到工序”产生CAM工序变更；“发布资源”只改变资源生命周期；“批准”核对对象和证据；“发布NC”属于后续CAP-10，不在本批用资源发布按钮替代。

编辑器不因UI已加载而启用命令。按钮可用性取决于后端Capability、Scope、读取修订和领域需求；正式命令必须再次校验。按钮禁用显示具体原因和修复入口。无权限仍可按政策读诊断，不泄露其他范围数据。

## 6. 指定边缘交互

表格/轴树区分焦点与选中；多选批量操作先列影响，不能把当前焦点误当全部选中。输入法合成期间不截获全局快捷键；输入框保留复制粘贴。ESC优先退出选择/关闭最内层临时对话，再返回任务；不默认取消长时作业。[R04]

表单修改遇到切范围：提供保存草稿、暂存、放弃、取消；返回时以当前真实修订重评估。几何参数解析失败时保留原场景和输入，不把NaN传给渲染器。模型替换时旧pick和旧PreviewLease回调必须失效。

未知任务进度显示当前阶段与取消可行性；完成通知不强抢焦点。[R01] 审批/错误/过期状态用文字+图形，不只靠颜色。

## 7. 评审原型与实际产品的边界

随包HTML提供十项页面切换、字段草稿、状态场景、浅深主题、专注空间、空间示意选择和资源选择返回。它不是完整页面实现，不包含真实后端、文件导入、Project保存、审批安全、Babylon或数控执行。每个结果都标示“演示回执”。

本批原型目的是让用户判断入口、状态、字段与流程是否清楚，而不是用看起来可用的按钮代替后端接线。产品实施时替换演示数据提供者，执行本批80+12个真实验收场景。

## 8. 建议实机验收基线

覆盖1366×768、1920×1080、125%/150%缩放、浅/深、键盘、减少动画和长文本错误。关键动作不被底栏遮挡；任务小节滚动不改变页面宽度；空/加载/只读/冲突/失败均可恢复。帧时、切世界内存与资源回收需在声明模型规模和参考硬件上测量，不能以固定FPS口号代替测量。
