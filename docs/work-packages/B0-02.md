## 1. 原V0.8定位、前提及交付边界

原V0.8要求：**「冻结能力责任与数据资产目录的首批条目」**，主责平台与集成，涉及11个业务域，**依赖B0-01**；交付11域/88项能力映射与修订日志、D01—D17唯一数据Owner及待决ADR；验收不得混淆88项与扩展提案、不得为同一权威对象建立两个写入边界，尤其要明确03/05/06中的特征、采纳、计算所有权。上述源文在`docs/architecture/v0.8/04_开发工作包_36项.md`；不得因本文件较详细就视为原任务实施完成。

**准入分层**：现在可以制定候选目录、规则、消费者评审表和测试规格；但B0-01仍只有原基线粒度，尚无经本任务确认的研发/集成/运行三份产品组合锁。**没有精确组合锁、Owner及消费方共同评审签字，不允许把本草案转成L3接口冻结，也不授予工程生产资格**。L1/L2维持V0.8已定的11域与88个原编号，L3逐项待评审，L4不由本工作包擅自冻结。

涉及的物理实现仓在原工作包中仅作为未来实施候选：`procet-gui`与`procet-contracts`；其它生产者/消费者包括`procet-cam`、`procet-solver`、`procet-resources`和相关工具。这些名称仅表示协作接线对象，不意味着仓库当前均已存在本稿建议的接口，更不表示已验证构建。**此次未改任何产品代码**。

## 2. 参与角色、真实生产/消费侧及责任决策

- **主责角色**：平台与集成负责人，维护基线映射、审查记录、C0最小共同契约和签署流程；不是11域内容的第二写入Owner。
- **各资产生产者**：02资源、03 CAD/PMI/制造特征、04 Setup/执行绑定、05工艺规划、06求解、07刀路、08 NC及执行语义、09工程验证、10发布/现场。每个D类资产恰有一个领域写入Owner。
- **消费者及评审者**：参照[17类资产Owner与拟议字段](B0-02/asset-owner-17-first-batch.json)列举的下游依赖域。所有Consumer负责证明自己只按版本化契约读，并按用途解释失效，不可代生产域批准。
- **横向宿主01域和AI/知识11域**：维护授权、任务、调用、投影、检索和可追溯的应用入口，**不因提供GUI/Agent/存储层而自动成为D01—D17的权威写入Owner**。11域Agent须调用与GUI/CLI相同的受控领域入口。
- **质量验证（横向）**：审查20个验收规格、原V0.8编号及双Owner冲突案例；文档检查、人工批准、产品测试分开出具证据。

**一致性决策**：一个逻辑权威业务对象只由一个领域命令处理写入。物理SQLite文件、缓存表、聚合投影和前端Store不改变其权威Owner。多个读取副本允许存在，但写回必须由原Owner通过版本化命令完成；涉及跨域变更采用新修订与补偿/重试协议，不凭空宣称多个独立存储存在统一ACID事务。

## 5. 首批跨域接口提案（不宣称存在）

**C0唯一最小承载**：`DomainRef(domain,kind,id,revision)`；`ArtifactDescriptor(contentHash,contentType,schemaVersion,producerProfileRef)`仅用于有文件/不可变输出工件的引用；`FrameRef`与显式`unitTag`只在涉及几何数值时要求，不能默认复制一个全局mm矩阵；`SourceRefs`关联直接依赖的exact内容。**C1由各领域各自扩展并版本化**；不应提供一个包括17类数据的巨型`common`结构体。

**跨GUI/CLI/Agent共用调用协议（拟议）**：`QueryExact{ref}`→`PrepareMutation{expectedRevision,expectedHash,context,previewOnly}`→ `CommitMutation{requestId,actor,scope,policyRef,expectedRevision,expectedHash,payload}`。提供`DomainEvent{eventId,domainRef,resultRevision,sourceRefs,classification}`与`Receipt{requestId,decision,resultRef,resultHash,observedGeneration,reason,requiresRefresh}`。**命令/字段是规划提案，不是已实现API**；实际域Owner必须确认具体格式、错误分类与幂等窗口。

提交点必须重验权限、目标精确修订、内容Hash、审批范围及租约；`advertised`仅代表登记，`backendReady`仅代表能力服务可用，`requestPermitted`是此次授权结果，三者都不是`committed`。HTTP中的RFC9110 If-Match只是条件提交类比；桌面IPC/CAS需单独设计并验证，不得声称天然实现RFC语义。

**事件和失败**：超时后若结果晚到，仅能作为特定`requestId`的可查询回执，不允许覆写当前`WorkContext`；点击取消不保证外部任务中断，但必须保证采纳仲裁；重复提交同一幂等键只能产生一次权威修订；未知必需字段`unsupported_required_schema`，过期revision`stale_revision`，字段单位不明`ambiguous_units`，未建模NC`unknown_controller_semantics`，缺批准`permission_or_approval_denied`，全部应带恢复动作而非显示`[object Object]`。

**五条关键生产链审查**：
1. `D01 → D02 → D05/D06`：CAD/PMI及确认特征Owner03；06仅识别/几何求解候选，05才采纳工艺。具体特征和机床选择均要求exact引用，不采用局部Face Index充作永久ID。
2. `D03 → D04`及`D03+D04 → D10`：工艺Setup可先存在；特定机床执行配置后置并与资源能力版本关联。
3. `D06/D07 → D05 → D08`：求解候选先被人工/规则采纳才能形成05域冻结，未批准不会升级生产资格。
4. `D08 → D09 → D12 → D13 → D14 → D15 → D16`：正式NC必须由最后写入字节做控制器语义解释、轴展开与覆盖验证，D11只是一条CL预验证证据。
5. `D16 → D17 → 受控工程变更 → D05/D06新修订`：现场回流是新的决策，不逆写已签发发布包。

## 7. GUI/CLI/Agent及3D治理工作台提案

B0-02本身是**规划治理工作包**，并不强制要求在产品中加一个“数据Owner设置”菜单。若后续增加供架构/评审人员使用的独立界面，应复用既有`Host/Project/ModuleRegistry/ContributionHub`和**左侧一个UnifiedTaskPanel**，采用五个任务页：`能力责任`、`资产Owner`、`接口消费者`、`冲突/ADR`、`评审与发布`。页面字段：`capabilityId`(只读/原V0.8)、`assetId`(只读)、`ownerDomain`(待审选择)、`schemaVersion`(版本号)、`expectedRevision`(只读)、`sourceHash`(只读)、`consumerReviewerRoles`(待签)、`approvalState`(只读)。不添加默认机床尺寸或虚构Frame。

右侧继续使用**一个Babylon交互世界**和主/资源虚拟空间切换，3D仅能高亮资产相关工件与来源路径，用`SelectionIntent`选、`PreviewLease`预览、显式Confirm提交相关Owner用例；治理评审的拓扑图/3D高亮均**不是写入数据、更不是审批**。切换文档或Setup释放旧预览租约，晚到异步回执必须校验`requestId+workContextEpoch+expectedRevision`。浅/深主题、键盘取消与面板宽度复用宿主已有贡献，不复制第二Scene或平行全局Store。GUI、CLI和Agent共用领域接口，不建立AI独占捷径。

## 8. 兼容、迁移、权限和回退

**兼容策略**：保留原V0.5/V0.7/V0.8源材料；老数据没有revision/hash/frame时标`needs_migration_review`并使用只读适配，禁止按`latest`猜默认。C0采用可版本化最小Envelope，C1由各Owner定义reader兼容窗口；未知可选字段可以保留为扩展但未知必需字段不得静默丢失。对于D13控制器语义，未知必需指令直接`unknown`且不得进入D15可发布结论。

**变更失效**：D01的设计版本影响相关D02/D04/D05/D06；D03资源修订影响使用它的D04/D10及后续链路；D12 NC字节变化使对应D13/D14/D15/D16资格失效；D17现场反馈不逆写D08/D16。失效用途应有规则版本、直接依赖Ref与可查询受影响范围，不能将所有主题/UI变更当业务失效。

**回退**：Owner/消费者评审失败只撤回此草案及导航delta，不影响现有产品；新契约实施后的回退必须保留已签名数据、转换日志、旧reader与冻结修订，先停写新schema，再采用已认证的兼容reader和可追溯新修订；不直接替换用户数据库或删除历史运行归档。
