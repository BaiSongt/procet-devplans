一个PR评审记录不是产品通过证明：需要区分GitHub自身状态、作者评论、独立验证日志、实际可运行二进制以及NC/实机工程验证。历史测试通过的最低适用粒度为**确切commit、测试命令、环境、输入/资产版本、受检范围、执行人和日志**。PR标题、绿色badge、简写SHA和空checks都不满足本包完整验收。

## 工作主流程与异常流

1. 收集repo、PR、head/base完整SHA、默认分支、采集时点、来源URL与访问深度，形成不可变Observation；PR修订后新增观察，不覆盖原记录。
2. 构建PR依赖DAG与审查快照，区分#62堆叠于#60的提交身份，复核开发分支与比较结果，不根据文件数猜ahead/behind。
3. 对当前HEAD收集reviews、check-status、测试日志、环境和执行者身份；将PASS_SCOPED、FAIL、BLOCKED、NOT_RUN、UNKNOWN、STALE、PENDING_REVIEW逐项分离。
4. 关联B0-01的开发源码HEAD、集成锁与运行实物三个层级，只生成建议排序与所需重验清单，不发产品操作命令。
5. 在唯一Host/Project通道接纳GUI、CLI、Agent审查提议，并经CAS、scopeEpoch与权限二次检查后提交**审阅草稿修订**；提交成功并不更改任何GitHub PR或工程业务资产。
6. 由平台/质量/GUI/Solver领域Owner交叉签审；缺独立验证时保留NOT_RUN，未知控制器语义、D04与D10不在本包补造；最终审批权仍属于各真实仓库Owner。

错误流：HEAD或base并发变化→STALE_REQUIRES_REFRESH；来源不存在→UNKNOWN；评论缺日志→EVIDENCE_UNVERIFIED；旧scopeEpoch、取消晚回执或权限撤销→ZERO_WRITE；修改受控分支建议未经批准→PERMISSION_DENIED；CAS冲突→CONFLICT并保留旧冻结结果。

## 数据接口、坐标与A/B冻结

建议只读对象PrEvidenceSnapshot包括repoFullName、prNumber、baseBranch/baseSha、headBranch/headSha、mergeBaseSha、collectedAt、sourceURL/sourceBodyHash、stackEdges、reviewCommitSha、requiredCheckContext(unknown可用)。VerificationReceipt包括observedHead、executor、reportAuthor、independenceLevel、platform、commands、exitCode、testCounts、artifactHash、evidenceURL、coveredScopes、excludedScopes。EvidenceDisposition按**子断言**而非PR单一布尔值储存。

**C0只提供最小身份、修订、hash、权限上下文、Frame/单位及协议包裹，不建巨型PR common模型。** 某测试与几何/坐标无关可标frame=not_applicable；若关联D04、D10须带确切Frame与AssetRef。A/B共享同一工程事实，但审查草稿不得覆盖05域冻结工序、D08冻结结果或既有D16发布。无运行NC不能将中立CL播放升格成D15验证；未建模控制器语义必须UNKNOWN，不做材料扫掠仿真。
