# E3-06｜D17离线独立消费者验收与交接

**此文件是验收协议草案，未发生真实接收、密码学验签、产品回归、实机/现场数据操作。**

## 受控准备材料
- D16发布包候选：NC字节Hash、D10机床配置及D12-D15 exact链、D08冻结版本、独立QA与人类批准事件、manifest字节与预期签名策略。
- 独立测试站：**预先**独立配置的受信根与允许签发者、离线吊销策略/最大允许新鲜度、隔离文件系统、校时策略；不可从同一不可信压缩包自动导入根密钥。
- 测试员：08/09提供验证金样，10域提供发布策略，独立D17消费者实际实现应由独立质量或现场试验人员运行；同作者的合成门禁输出不得代替结果。

## 接收检验顺序
1. 冻结接收前的预期发布者、工程作用域、目标控制器/机床以及受信根版本，记录独立配置的精确哈希。
2. 解包前检查最大大小、对象数、归档路径及路径重名/符号链接/绝对路径/..等；解包后按**原始字节**重算逐文件SHA-256。
3. 对版本化的规范化Manifest验签并比对发布主体digest、签名签发者、受信根、吊销策略及内容清单。未知语义/未知密钥/必需吊销状态未知均拒绝或阻断，不自动降级。
4. 对本地D03/D10允许列表重新比较机器、控制器方言、刀具配置和实际WCS；与包不一致须重新审查，禁止凭包自述设置真实机床。
5. 按包摘要+站点+策略的幂等键追加D17回执；接收并不触发设备G-code执行。回执应记录本地系统钟是否可信、在线/离线、查验结果及人工接收人。
6. NC更改、批准撤回、签名失效、过期授权、离线复核失败/晚回执/重复回执发生时，输出可复现的拒绝证据，不能覆盖旧历史。

## 工程负例集合及验收边界
- 对齐：原始NC hash、manifest hash、签名subject、D15 run的input revision及执行配置精确一致。
- 篡改：NC改1字节、路径穿越、附件缺失、混入未列文件、换keyId、过期撤销数据、错控制器、人工批准缺失。
- 生命周期：撤销后原包只读、双版本同名不同Hash拒绝、重复相同回执幂等、丢失D17回执为UNKNOWN。
- 隔离：断网操作不得泄漏密钥或隐式联网；现场纸质人工放行及机床实际传输保留独立流程。
