# F1-03｜边界审计、接线与迁移状态

2026-10-18评审稿。关联[工作包](../F1-03.md)、[理论专题](../../../research/topics/R-BOUND-001.md)。所有字段为设计提案；不意味着产品已有对应DTO或运行检查。

## 1. 能力调用的四层事实

| 层次 | 数据来源 | 可以回答 | 不应推定 |
|---|---|---|---|
| 能力声明 | 受信模块描述 | 软件声明提供哪些能力 | 已安装真实处理器 |
| 处理器与依赖就绪 | Host、实际领域适配器 | 当前是否可受理这种调用 | 任意用户/任务已获准 |
| 本次请求许可 | 领域用例、授权与批准检查 | 当前输入和作用域是否允许执行 | 结果已经提交 |
| 结果回执 | 真实事务提交记录 | 哪个修订已经提交、结果属于谁 | 所有下游验证也已通过 |

执行条件为已绑定处理器、依赖就绪、Schema兼容、作用域合法、权限合法、所需批准有效和输入修订匹配的合取。UI显示的条件只能用于提示；正式请求与提交点仍由后端核验。未知必需条件按未满足处理，能力目录可保留解释性禁用条目，但不能将其列为可执行集合。

## 2. 同一用例的接线记录

| 列名 | 谁填写/含义 | 校验要求 |
|---|---|---|
| businessCapabilityId / useCase | 产品Owner；CAP及实际业务动作 | 不用页面名代替业务边界 |
| caller / compositionRoot | GUI、CLI、Agent及实际装配点 | 自动/动态注册也要列出 |
| declaredCapabilityId / handler | Host和CAM；目录与已存在处理器 | 能力目录和处理器对拍，不推导授权 |
| ownerDomain / writeSet | 数据Owner；权威表、资产和受控写入 | 包含DAO、触发器和外部副作用 |
| inputRefs / expectedRevision | 领域解析的exact输入 | model/setup/resource/frame/hash及版本明确 |
| requestId / routeEpoch | Host；一次请求的去重与路由身份 | 在途重试不跳转第二个writer |
| policyRef / approvalRefs | 服务端政策及业务批准 | 不是前端勾选或Agent自报 |
| receiptRef / outputRefs | 服务端真实提交结果 | 结果丢包时按requestId恢复，不重复生成 |
| retirementEvidence | 实施Owner与消费方 | 支持组合、测试、迁移与回退记录齐全 |

一个领域可以有多个合法数据库连接/事务；“单一writer”指唯一权责域与受控入口，不等于全应用只能有一个连接。作为组合根的Tauri胶水可以装配真实adapter；禁止的是越过用例/权限直接修改权威数据，不是禁止所有宿主import。

## 3. 固定审计列表的盲点

已读CAM@fcec1c86的boundary_audit.rs把3份facade和7份ports文件列在常量数组中。新文件不会自动进入扫描。因此必须同时维护“实际模块集合”和“已审计集合”，对未覆盖项明确失败或待审，而不是根据旧10个文件通过宣称全层通过。

manifest检查还只处理以path开头的行。以下是用于检测设计的合成片段，不是产品新增依赖：

```toml
[dependencies]
example = { path = "../other" }
```

旧逐行形式不能覆盖上述写法。整改需要结构化解析TOML、工作区继承、target/build/dev依赖和解析后的路径；合法工作区内部路径、受控本地覆盖与禁止生产旁路分别定义。不将所有`..`一律判错，最终须以声明仓界、符号链接解析和产品组合政策判断。

AST和文本检查各自有覆盖边界。运行期观察只证明所执行场景的写入行为；不能据未观察到某条调用就证明永远无消费者。F1-03-T19必须包含新增文件、内联path、间接DAO和动态注册四组反例。

## 4. 迁移与回退状态

每条能力使用“观察→适配就绪→只读对拍→切换待验证→新入口生效→旧入口退役”的受控状态。推进需具体产物和Owner/消费者复核，不由执行次数决定。

只读对拍固定输入快照；隔离副作用和产物命名空间，不发布NC、不调用设备、不双写资源。一次调用固定routeEpoch；故障时先查原requestId的receipt，确认尚未提交且动作可安全重试后，才按政策处理。不能因新adapter超时就直接调用旧writer重发。

回退分三层：命令路由回退；二进制/组合锁回退；数据格式与快照恢复。新格式已写入而旧reader无法读取时，必须保留新reader或执行已验证逆迁移，不能仅回退代码。迁移期间旧副本是受控兼容来源而不是新的权威Owner；来源不完整或修订不可解释时只读/阻断。

## 5. GUI中的业务表现

用户仍操作原CAP页面，不引入一个要求用户选择“旧算法/新算法”的技术工作流。资源不可用时显示具体缺失项与修复入口；能预览不等于能提交。dirty关闭保留保存/放弃/返回语义，冲突保留两边草稿，重试显示是否复用旧requestId。

3D只消费显示数据与已核对选择引用；正式Apply走同一领域用例。工程A的旧回执不能改工程B；主/资源空间切换不能重建第二个主交互Scene。诊断详情可显示adapter版本/来源，但不得暴露客户文件路径、密钥或内部SQL。
