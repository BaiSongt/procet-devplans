## 1. 设计目标与版本纠偏

**要解决的用户问题：** CAD工程师/工艺师/求解研究人员希望在项目中从冻结设计与材料约束直接发起有预算的通用求解，看清候选顺序、几何变更、来源、收敛和不可验证项，保存可离线重放的真实工件，再由工艺人员决定是否采纳；无需准备研究目录、手动配置Python环境或读取散落的日志。可不依赖已批准机床执行配置进行适用的探索，但材料状态求解必须有明确初始Stock及Frame。

V0.8 F1-05原句包含“锁定 Python/OCP 环境；现有 G6 桥接适配”。**2026-10-18实时读取 solver develop@`44172bc046bfd65c2a4fe36212536c70226be48f` 后，不能再假定 Python 是默认生产内核**：solver-sdk与CLI的Cargo默认`native-occt`，原生迁移台账声明Rust+OCCT 7.9.3生产链和Python/OCP独立对照链；workspace标记0.4.1。本文保持工作包的“受管入口/版本锁定/可验证边界”目标，将执行实现分为 **主生产Rust+原生OCCT冻结profile**、**独立Python/OCP对照profile（非生产回退）**、**旧Python G6历史只读兼容profile（不得静默提升资格）**。这项解释属于**待L3审批的实施方案修订**，不擅自改V0.8的历史正文，也不等于已验收生产包。

### 确认的能力上限，不可合并成一个数字

现有迁移台账分别记载“独立Oracle全枚举1..5特征合法顺序”、“前沿搜索最多12特征”、“某些材料记录可至128步”等**不同算法的局部上限**；完整G5证据链当前仍必须按**1..5特征**报告其受支持范围。产品入口须按实际algorithmId/profile读取能力声明和预算，超过范围显式blocked或unverified，不可用12/128冒称完整通用求解已认证。SDK/CLI虽然默认原生构建，但用户部署机的OCCT SDK、运行库哈希、worker可用性仍须独立检查。

## 4. 主、替代、异常业务流程

**主线：** 选择已有工程/设计修订→选取目标/Stock及受限资源约束→能力预检显示可运行profile与真实范围→用户设算法/预算/验证方式→提交`SolverRunRequest`形成冻结输入和`requestId`→worker执行产生D06/D07、trace与独立核验工件→复读manifest与证据→列表/3D联动对比候选→明确“仅候选/可复核/需人工审批”的资格→工艺域显式采纳并保留来源（不自动修改D05/D08）。

**替代流A（无已批准工艺计划）：** 在权限允许下启动探索，缺计划不应阻断可独立运行的Geometry/Feature探索；若要求材料演化，则缺Stock/Frame必须明确阻断相关能力。**替代流B（离线与兼容）：** 现有RunPackage经哈希和schema核验后只读打开；历史Python/G6档案保留原身份和未知语义，若需升级产生新run和新资格记录，不覆盖原档。**异常流：** 原生动态库不匹配、源码或拓扑SHA变化、预算耗尽、超时、取消、worker坠溃、manifest损坏、跨版本未知必需字段、恢复重复请求，均必须有稳定错误码与安全状态；不生成看似已完成的D07或Plan批准。

## 6. 冻结/回退与阶段出口

只有受管SDK/Worker接口和真实工件验证均符合约定，才允许把某一个已验收能力切至新路由。旧Run/Plan冻结修订不就地重签、不重跑覆盖、不以Python或其他插件自动兜底。回退采用**新的route/config revision**和明确的读回执；旧数据继续可打开且状态未知项可追溯。阶段退出包含跨Windows/Linux离线安装、无研究目录、无下载、真实OCCT、预算/取消/内核失效、1..5完整G5及完整manifest重放的有界回归证据；未来更多算法另建验收范围。产品执行测试本轮全部**未运行**。
