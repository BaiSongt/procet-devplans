## B. 独立验证要求

每条分别记录input rootId/sha、具体依赖缺失或干扰方式、预期/实际状态、source/target环境、精确源码HEAD、断言、日志和恢复后工作区fingerprint。反例至少由测试方独立构造，不能调用被测导出器直接生成全部golden而不核对内容。实体资产只使用合法公开/自造合成数据，禁止客户资料入测试仓。

验证维度：独立新进程且无网络；Windows 11、Ubuntu/WSL路径规则；多次打开/关闭；多Setup；同一源文件多个版本；大文件限额与低存储；真实Host provider/Reader/CAS；强杀前/后和重启恢复；C1消费端独立对拍。容器字节读取通过只是第一层，还需CAD/Setup/Resources等领域消费成功，最后才可能宣称该范围快照可用。

计划用例T01—T20覆盖：S01库存闭包、S03必需分级、S04一致切面、S05格式、S06安全、S07隔离恢复、S08迁移、S09交互、S10故障。**本轮未执行任何一条。**

## C. 完成门与延期

完成门必须是20/20产品测试的具名exit 0/PASS回执，实际消费者按用例覆盖；跨仓exact HEAD核对；无阻断失败；S01—S10所有正式产物和迁移/回退演练完成。若某设备控制器/授权插件或数据无法取得，应按限定能力标unsupported并明确从退出范围剔除及风险审批，不能用“常规型号适用”隐性放行。

长期开放研究：跨平台替换耐久性保证、云同步与跨机器分布式一致、实际控制器NC语义、私有机床OEM资产许可与数字签名链。它们不要求在F1-06中全量实现，但不能在系统发布说明中冒称已覆盖。
