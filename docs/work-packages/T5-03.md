## 原目标及责任边界
[原36项原文](../architecture/v0.8/04_开发工作包_36项.md)：产品组合清单、Producer/Consumer兼容矩阵、本地发布候选验收包；二进制hash必须与被测组合相同，必需旧消费者回归不能缺席，任何失败域不得被整包PASS遮蔽。安装包与版本组合锁成对回退，禁止浮动develop构建发布。主责01域平台集成，前置E3-06/U4-05/B0-06；目标产品涉及procet-gui和procet-contracts，本轮**仅读产品信息、绝不修改产品仓**。

## 真实发布业务链与约束
1. ReleaseCompositionLock区分研发源HEAD、GUI实际消费锁、最终installer字节Hash三种事实；精确记录仓SHA、包/ABI、平台OS/arch、Native/Worker、构建器、第三方许可和签名版本。私有产品源SHA只能进入受控交接清单，**不得公开于public规划仓**。任何浮动引用、未核二进制均为LOCK_UNKNOWN。
2. ProducerConsumerMatrix逐接口登记生产者/消费者精确源和binary锁、Port、Schema、ABI、Frame、数据版本与独立进程的PASS/FAIL/UNKNOWN/NOT_RUN；SemVer只能用于版本策略，不能推断真实业务兼容。旧reader在实测与审批前不得退出。
3. 来源证据分解成exact artifact bytes SHA-256、构建inputs/builder、SLSA attestation（可选但不得虚构）、许可SBOM、验签公钥与签收者；RFC8785仅作为规范化候选，实际尚未实现，禁止拿默认JSON.stringify伪装规范哈希。
4. 资格为逐能力、逐域、逐组合而非全包一个布尔值。规划静态PASS、实际产品测试、真实跨域消费者、人工审批和离线安装分别记账。缺日志或日志对应另一SHA必须NOT_RUN/STALE，不能借历史绿灯。
5. D04 ProcessSetup与D10 ExecutionBinding分离；D09中立CL→D12最终NC后处理→D13基于实际NC字节解释控制器语义→D14轴时序→D15独立程序级验证→D16人类批准发布。CL动画和D11预演不是D15，D13未知语义必须UNKNOWN并阻止发布；**不做材料扫掠仿真**。
6. 离线接收需受控Windows安装包与成套Native/Worker依赖、manifest、许可证、信任根/验签工具和精确hash；若用Tauri updater则签名必要，不能把普通hash当签名。TUF仅提供回滚/冻结/混搭攻击模型，尚未部署；吊销无法更新必须显式UNKNOWN。
7. GUI、CLI和Agent使用同一个01域协调查询/10域ReleaseOwner受控签发Port。Owner原子提交之前再次校验ACL epoch、expectedHead CAS、revision/hash/Frame（适用时）、scopeEpoch、taskGeneration及cancelToken；取消和切工程后的晚回执只能记旧任务审计，不可提交新签发。人类D16签发不可由模型文字代替。
8. 执行Expand/Migrate/Contract：先保留旧reader，新旧组合独立验收且恢复测试通过才退役旧实现。失败时成对回滚installer和composition lock，保留原始用户工程、数据库、冻结D08和发布历史，不能删库重建。
