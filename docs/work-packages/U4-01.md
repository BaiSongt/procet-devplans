## 二、导航身份与恢复数据
- `WorkContextRef={projectId,documentId,documentRevision,documentHash,setupId,setupRevision,setupHash,frame:{id,revision,hash},scopeEpoch}`，引用均由Owner签发，且作用域与租户隔离；一个文档可有多个Setup，缺失必须显式STALE_MISSING。
- `PresentationContext={workMode:'A'|'B',displayMode:'WORKBENCH'|'AI3D'|'FOCUS3D',leftTaskId,focusTarget,sceneLeaseId}`只是展示，不拥有制造事实。切换workMode仅改变用例前置和可用命令，不重写已批准工艺。
- `NavigationIntent={from,to,expectedScopeEpoch,taskGeneration,dirtyResolution}`；切换前需处理编辑会话，scopeEpoch递增，失效前一代请求；恢复必须重新查询Owner exact引用并做权限检查，而不是信任localStorage缓存。
- 本地history仅保留非敏感路由线索，不写持久授权或冻结快照；离线打开时先校验工程/文档/Setup的真实可用性。

## 四、关键状态机与异常
`IDLE → GUARD_EDIT → CANCEL_OLD_SCOPE → LOAD_EXACT → CONFIRM_SCOPE → RENDER`。
失败分支：`DIRTY_EDIT_REJECTED`、`STALE_MISSING`、`ACCESS_REVOKED`、`REVISION_CHANGED`、`TASK_CANCELLED`、`UNKNOWN_RECOVERY`。切换并非持久Owner写入，故成功导航不返回任何制造资产新revision；若保存草稿则另走领域Owner写Port并确认独立回执。
UI关闭/重开、后退/前进、双文档切换、切换Setup、后台迟到响应、权限撤销、旧书签指向已删除资源均须有正反例。导航没有“自动认可”求解、刀路或机床验证的权限。
