## 目标与现场问题
用户点选最终NC实际程序字节中的某个Block，能够在同一工作上下文中定位D12原始NC修订→D13控制器规范动作→D14具体轴指令/采样区间→D15验证事件与覆盖范围；反向点选报警事件也应追溯NC字节区间、D10执行配置、来源D08冻结及特定Setup。并行地显示D06真实搜索收敛/失败原因及W2-03失效闭包。**缺失不可猜、未知不可冒充已执行，历史证据不可覆盖。**

## 固定边界与数据主权
[原36包基线](../architecture/v0.8/04_开发工作包_36项.md)保留原交付/验收/依赖。11域、88 CAP、36原工作包、17资产及L1/L2不变，L3待审；C0只有identity、units、frame、revision/hash、scope和协议。D04名义工艺Setup是制造前提；D10是实际机床/控制器/刀具/工件偏置的**执行绑定**，两者绝不合并。

诊断投影不拥有D06/D08/D12/D13/D14/D15/D16任一领域事实，不向Shell导入大Store。D12程序定位用 **NC bytes hash + 字节偏移区间 + Block序号 + 后处理修订**，可读N号仅显示，不能作唯一主键：公开LinuxCNC 2.9手册允许N号重复、乱序。D13动作可为一对多或未知，D14事件可为时间区间映射；采用多对多边表，缺边显示SOURCE_GAP，不能用最近邻N号或相同路径形状补边。

**中立链路：** D09 CL → D12后处理的最终NC → D13执行语义 → D14轴时序 → D15独立NC验证 → D16审批发布。D11仅CL级预检查。无法建模的控制器循环/宏/偏置返回UNKNOWN，不能获得D15或D16工程通过；只画图和检查轴运动，不开发材料扫掠仿真。A/B复用同一Owner事实，不覆盖D08冻结。

## 领域端口与事务
`DiagnosticQuery.readExact({WorkContextRef,D12ContentRef,BlockRangeRef,D13ActionRef?,D14EventRef?,D15EvidenceRef?,scopeEpoch,aclEpoch})`由各业务Owner返回不可变快照与显式缺边；`DiagnosisPort.listConvergence(D06RunRef)`仅返回Owner保存的迭代样本；`InvalidationPort.getClosure(changedExactRef,dependencyRevision)`返回确证影响及UNKNOWN_SCOPE。查询方禁止把D06打分转成概率，禁止把OpenTelemetry Span状态映射成D15 PASS。

写操作不是“修正诊断”直接改权威数据：`EditSession.openIntent→owner.X.commitCAS(expectedHead,currentAclEpoch,scopeEpoch,generation,permission,approvalRef)`。D08冻结为只读，已取消/并发Head变化/ACL撤销返回拒绝。回执持久化在Owner侧，Scope变化之后的迟到响应只作为历史诊断；幂等重放不得产生第二份业务事实。来源图类型可有反馈，**具体精确修订DAG必须无环**。
