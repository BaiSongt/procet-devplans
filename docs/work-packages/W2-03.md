## 原始目标和可证伪边界
原交付为“**版本化资产DAG、领域影响规则、失效原因查询**”；原验收为“NC编辑只传播到相关执行链；主题变化不使制造资产失效；资源状态与内容完整性分别判定”；原回退为“保留历史图、规则升级版本化并可重建派生索引”；原明确不做“全部业务反馈误建成可变来源环”。本轮不修改L1/L2及36包总表，仅细化原W2-03。

## 事实与责任边界
1. **两种不同的图**：17类业务资产的**类型交互图可以出现反馈**（D17→下一轮D05/D06）；实际每条`assetId@revision@hash@scope`因果引用必须构成有向无环图。D17反馈追加事件并经审批**生成新版本图**，不把未来产物逆接到旧D05/D08。
2. **业务Owner唯一写入**：01域只维护依赖规则版本、失效事件、查询投影和解释；D04原始Setup归04域，D10执行绑定是单独资产；D05/D08归05域且D08历史不可变；D06/D07归06域；D09归07域；D12/D13归08域；D14/D15归09域；D16/D17归10域。17类Owner候选仅用于接口评审，正式跨域会签为PENDING。
3. **精确参考**：每个输入引用至少id、revision、内容hash、Frame（非几何需`NOT_APPLICABLE`并解释）、unit、scope、branch、规则版本及计算服务版本；引用失效先影响资格，不能自动销毁旧数据。哈希类型须注明字节哈希还是规范化对象哈希，D12最终NC必须核对原始字节。
4. **失效不是破坏性写入**：修订后旧资产保留、历史D08冻结绝不覆盖。生成`ImpactDecision`：受影响旧版集合、各自原因路径、完整性/可用性/有效性维度、下一步消费者审查/重算、未覆盖UNKNOWN和原因码。撤回只追加新修订，旧图仍可重放。
5. **工程链的最小闭包**：D05可交给D06，D09必须独立持D07材料状态+D08冻结；D09中立CL→D12最终NC→D13控制器语义→D14轴运动时序→D15独立NC程序级验证→D16发布。D11仅CL级运动预验证，永不能冒充D15；D13未知语义返回UNKNOWN；本轮不做材料扫掠仿真。

## 业务流程
读取版本图/规则版本→域Owner提交带精确来源的变更提案→只读预览按**改动类型、范围、依赖边、旧版修订**计算最小候选受影响集合→显示“为什么失效”路径及不会失效的资产→人类裁决/必要批准→提交时重新查权限/项目scope/branch/Frame、CAS头、任务代次和取消晚回执→append-only记录新修订与失效判定→各域消费者从自己的原始事实独立复核→可重建只读投影/审计与回退。若图有环、引用不全或规则版本漂移，停在REJECTED/UNKNOWN，禁止静默扩大“全局PASS”。
