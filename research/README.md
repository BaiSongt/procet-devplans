## 证据分层

| 类型 | 可以证明 | 不可以证明 |
|---|---|---|
| 标准目录/摘要 | 标准身份、版次和适用主题 | 未读条款、具体尺寸、软件已合规 |
| 标准正文/原始论文 | 已读取范围内的定义、算法和前提 | 超出试验范围的普适效果 |
| 官方设备/控制器手册 | 指定型号与版本的接口、行为和限制 | 所有厂商、所有固件的行为 |
| 官方实现文档/源码 | 指定提交的实际结构和能力线索 | 产品组合已消费或已验收 |
| Procet设计推导 | 在声明前提下选择的规则和实现方案 | 文献作者已经验证Procet |
| 可重放测试证据 | 精确版本、输入与环境下的测试结果 | 未测型号、拓扑、容差和安全资格 |

访问深度枚举：catalog_abstract、section_text、full_text、not_obtained。标准全文需合法获得，禁止通过第三方盗版替代。访问深度不是权威等级，来源权威也不能补偿没有读到相关内容的问题。

每个来源记录标题、作者/机构、版次/发布日期、URL或DOI、访问日期、读取位置、支持结论、适用范围、未覆盖内容。未知日期写未标注，不把爬取日期当发表日期。参考当前官方版本时要核对替代版、勘误和修订；历史手册仅用于其明确版本或原理反例。

## 必须形成的追踪关系

来源ID → 理论或工程规则ID → 字段/公式/状态变化 → CAP与工作包 → 正向/反向验收ID。

没有外部来源的内部架构选择可以合法存在，但必须标为设计决策，给出理由与验收，不伪称行业标准。来源冲突时比较控制器版本、坐标约定、工具类型和实验条件，不用多数表决掩盖语义差异。对影响安全或核心计算的未知值，设计必须保留阻断与补证路径。

## 编制完成口径

一个专题需给出可复核原理、已核对来源、Procet适用规则、失败边界、字段映射与验证设计。必要正文无法获取时写清补证责任与冻结限制；不能把未知工程规则当作已确认。最终规划可保留待人类批准和待实机测试，但不能保留未说明的关键计算语义。
